07/14
Platform Decision

為什麼是 Worker + GitHub Actions

GAS

6 分鐘執行上限，STT + 摘要遠超時。

n8n / Zapier

要 self-host 或付費。

自架 VM

要顧機器，也要錢。

Cloudflare Worker

edge dispatcher，免費 100K req/天，秒回避免 timeout。

GitHub Actions

30 分 timeout 扛重活，免費 2000 min/月，產物直接進 repo。

Worker 只做秒級事：驗簽 + lock + dispatch。
重活全丟 Actions。

dispatcher vs workload

Pipeline

五節點資料流轉：重點不是呼叫 AI

STT

speech to text
輸入：LINE m4a 音檔輸出：簡體逐字稿

校正

normalization
輸入：簡體逐字稿輸出：繁中校正稿

摘要

structure
輸入：校正稿輸出：議題/決議/行動 JSON

驗證

grounding
輸入：摘要 JSON + transcript輸出：通過引用的內容

分發

delivery
輸入：結構化摘要輸出：meeting note + LINE 回推
每段都明確改變資料形態，AI 呼叫只是其中一種加工方式。

12/14
Anti-Hallucination

責任歸屬不能編造

「會議摘要不可假造，尤其是任務安排，這會有責任歸屬的問題」

引用強制

每條決議/行動附 transcript quote。

指派 vs 提及

請 X 做 Y ≠ 跟 X 對這題。

fail-loud

不確定標「待確認指派」；寧可漏記，不可錯記。

ownership requires evidence

Design Philosophy

設計哲學四原則

01

入口秒回

Worker 只做驗簽、白名單、lock、dispatch。

02

重活後送

STT、校正、摘要、驗證都交給 Actions pipeline。

03

資料契約清楚

每段都明確定義輸入、輸出與失敗處理。

04

invariant 寫進會被讀的文件

重要約束放程式註解 + 架構文件，不只 commit message。
